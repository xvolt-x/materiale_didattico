1Qualità di un algoritmoSul libro · pp. 38-39

Correttezza ed efficienza

Un buon algoritmo deve avere due qualità. Non basta che arrivi alla risposta giusta: deve arrivarci in un tempo utile e senza sprecare risorse.

Correttezza

L'algoritmo fornisce la soluzione del problema proposto.

Efficienza

L'algoritmo fornisce la soluzione in un tempo utile, con un uso "ragionevole" delle risorse di calcolo: tempo macchina (numero di istruzioni eseguite dal computer) e memoria.

Come si misura l'efficienza?

PROVA A RISPONDERE

Per sapere quanto è efficiente un algoritmo basta misurare il tempo di esecuzione del programma che lo implementa?

clicca per girare la carta

Non basta. Lo stesso algoritmo può impiegare 2 secondi sul PC di casa e 0,5 secondi su un server: il tempo misurato dice qualcosa sul computer e sul programma, non solo sull'algoritmo. Serve una misura più astratta: la funzione di costo.

Tempo di esecuzione

Dipende da numerosi fattori:

  • il linguaggio di programmazione utilizzato;
  • l'efficienza con cui il compilatore o l'interprete traduce il codice in istruzioni macchina;
  • le caratteristiche tecniche del computer;
  • gli altri programmi in esecuzione nello stesso momento.

Funzione di costo

È un metodo di valutazione più generale e "astratto": conta quante operazioni elementari esegue l'algoritmo, indipendentemente dal linguaggio in cui è scritto e dal computer su cui gira. Questi fattori cambiano quanto dura ogni operazione, ma non quante operazioni servono.

Poiché la dimensione dei problemi varia con la quantità di dati in input, il costo si esprime come una funzione di n, la dimensione dei dati.

2Contare le operazioniSul libro · pp. 40-41

La funzione di costo T(n) e la tabella di traccia

La funzione di costo T(n) misura il numero totale di operazioni elementari necessarie per completare l'esecuzione di un algoritmo, in relazione alla dimensione n dei dati di input. Se T(n) cresce lentamente al crescere di n l'algoritmo ha alta scalabilità; se cresce rapidamente, ha bassa scalabilità.

Per capire come si calcola, partiamo da tre funzioni che stampano asterischi:

  • print_row(n) stampa una riga di n asterischi;
  • print_triangle(n) stampa un triangolo di n righe;
  • print_square(n) stampa un quadrato di n×n asterischi.

Per ognuna scriveremo il codice Python, conteremo le operazioni in funzione di n, misureremo il tempo di esecuzione e confronteremo i grafici.

print_row(n): una riga di asterischi

Accanto a ogni istruzione scriviamo quante volte viene eseguita. Il confronto j < n viene valutato n+1 volte: n volte risulta vero, l'ultima volta falso e il ciclo termina.

def print_row(n):              # Operazioni
    j = 0                      # 1
    while j < n:               # n + 1
        print("*", end="")     # n
        j += 1                 # n
    print()                    # 1
                               # totale = 3n + 3
Sommando le operazioni: T(n) = 3n + 3  → funzione lineare

È un polinomio di primo grado in n: il suo grafico è una retta. Il motivo si vede nel codice: c'è un solo ciclo, che viene eseguito n volte e a ogni giro fa sempre lo stesso numero di operazioni. Se n raddoppia, le operazioni circa raddoppiano (303 con n = 100, 603 con n = 200).

La tabella di traccia

La tabella di traccia (trace table) serve a simulare a mano l'esecuzione di un programma per verificarne il funzionamento. Ogni riga è un passo di esecuzione; le colonne sono le variabili, le condizioni logiche e l'output. Qui sotto aggiungiamo anche una colonna che conta le operazioni eseguite fino a quel momento.

print_square() e print_triangle()

print_square(n): un quadrato n×n

La funzione chiama n volte print_row(n). Ogni chiamata costa 3n+3 operazioni, più 1 per la chiamata stessa.

def print_square(n):           # Operazioni
    i = 0                      # 1
    while i < n:               # n + 1
        print_row(n)           # ((3n + 3) + 1) * n = 3n² + 4n
        i += 1                 # n
T(n) = 3n² + 6n + 2  → funzione quadratica: cresce molto più rapidamente

print_triangle(n): un triangolo

Un triangolo è una sequenza di righe lunghe 1, 2, 3, … n asterischi. Come print_square, anche print_triangle può quindi riusare print_row: alla riga i stampa i + 1 asterischi.

def print_triangle(n):         # Operazioni
    i = 0                      # 1
    while i < n:               # n + 1
        print_row(i + 1)       # (3·1+4) + (3·2+4) + … + (3·n+4)
        i += 1                 # n

Qui le cose si complicano un po'. La chiamata print_row(i + 1) costa 3(i + 1) + 3 operazioni, più 1 per la chiamata, ma il costo cambia a ogni giro: la riga è lunga 1 quando i = 0, 2 quando i = 1… fino a n quando i = n − 1. Sommando tutte le chiamate:

(3·1 + 4) + (3·2 + 4) + … + (3·n + 4) = 3·(1 + 2 + … + n) + 4n

Per calcolare la somma 1 + 2 + … + n serve la formula di Gauss.

La formula di Gauss: 1 + 2 + … + n = n(n+1)/2

L'idea: scrivere la somma due volte. Chiamiamo S la somma 1 + 2 + … + n. Con n = 6 la scriviamo una volta in avanti e una volta al contrario, poi sommiamo le due righe colonna per colonna:

S=1+2+3+4+5+6 S=6+5+4+3+2+1 2S=7+7+7+7+7+7

Ogni colonna vale 7 = n + 1: quando il numero sopra sale di 1, quello sotto scende di 1, quindi la loro somma non cambia. Le colonne sono 6 = n. Allora 2S = 6 · 7 = 42 e S = 21.

Con un n qualsiasi il ragionamento è identico: ci sono n colonne, ognuna vale n + 1, quindi

2S = n(n + 1)  ⇒  S = 1 + 2 + … + n = n(n + 1)2

Lo stesso ragionamento, disegnato. La somma 1 + 2 + … + n è una "scala" di quadratini (in azzurro): 1 nella prima riga, 2 nella seconda, fino a n. La seconda riga del calcolo qui sopra è la stessa scala capovolta (in arancione). Accostate, formano un rettangolo di n righe e n + 1 colonne: la scala azzurra ne occupa esattamente metà. Muovi il cursore per vederlo con diversi valori di n.

Il triangolo costa circa metà del quadratoIl termine dominante è 3⁄2n² contro 3n² di print_square: il triangolo stampa circa metà degli asterischi del quadrato. Per n grande il costo è circa la metà, ma la crescita resta quadratica: stessa classe O(n²), fattore moltiplicativo dimezzato.

Misurare il tempo di esecuzione in Python

  
Il numero di operazioni T(n) è una previsione. Ma i tempi reali seguono davvero la stessa forma? Per scoprirlo dobbiamo saper misurare il tempo in Python.


  
La libreria time

  
La funzione time() restituisce il numero di secondi trascorsi dall'epoch, l'istante da cui inizia il conteggio del tempo. Nella maggior parte dei linguaggi è la Unix Epoch: la mezzanotte (00:00:00) del 1° gennaio 1970 UTC. La funzione gmtime() converte un numero di secondi in un oggetto time.struct_time espresso in tempo universale coordinato (UTC).

  
import time
t = time.time()
print(f"{t:,}")
print(time.gmtime(0))     # l'epoch
print(time.gmtime(t))     # adesso

time() e process_time()

  
Le due funzioni misurano due tipi diversi di tempo.

  

    

      
time.time()

      
    
        
  • Restituisce il tempo reale (wall-clock time) in secondi dall'epoch.
    • 
        
  • È influenzato da ritardi del sistema, sleep, carico della CPU, cambi dell'orologio di sistema.
    • 
        
  • Serve per misurare durate reali, timeout, timestamp.
    • 
      

      
import time
start = time.time()
time.sleep(2)
print(time.time() - start)   # ~2.0 secondi

    

    

      
time.process_time()

      
    
        
  • Restituisce il tempo di CPU usato dal processo, escluso il tempo trascorso in attesa.
    • 
        
  • Non misura il tempo reale, ma solo il tempo in cui la CPU lavora per il tuo programma.
    • 
        
  • Non è influenzato dal carico di sistema né dall'orologio. sleep() non usa la CPU.
    • 
      

      
import time
start = time.process_time()
time.sleep(2)
print(time.process_time() - start)   # ~0.0 secondi

    

  


  
elapsed_timeLa differenza tra due chiamate di process_time() viene chiamata elapsed_time. In realtà non è il tempo trascorso tra le due chiamate, ma il tempo che la CPU ha dedicato al processo in quell'intervallo. È proprio quello che serve per valutare il tempo di esecuzione di un algoritmo.


  
Misurare print_row(n) al crescere di n

  
Il programma esegue print_row(d) per d = 0, 10, 20, …, 90, misura ogni volta il tempo con process_time() e disegna il grafico dei tempi.

  
import time
import matplotlib.pyplot as plt

def print_row(n):
    j = 0
    while j < n:
        print('*', end='')
        j += 1
    print()

dims = list(range(0, 100, 10))
times = []
for d in dims:
    t1 = time.process_time()
    print_row(d)
    t2 = time.process_time()
    diff = 1000 * (t2 - t1)          # millisecondi
    times.append(diff)
    print(f"t_exe={diff:.2f} ms")

plt.plot(dims, times, '*r')
plt.xlabel('n')
plt.ylabel('execution time [ms]')
plt.title('funzione print_row(n)')
plt.show()

  
Il risultato: i punti misurati si dispongono (circa) lungo una retta, proprio come T(n) = 3n + 3. Con print_square si dispongono invece lungo una parabola. La forma della crescita prevista dalla funzione di costo si ritrova nei tempi reali.

def sum_while(v):
    """Somma i valori dell'array v con un ciclo while."""
    i = 0                  # Assegnazione          1
    sum_ = 0               # Assegnazione          1
    while i < len(v):      # Confronti             n + 1
        sum_ += v[i]       # Addizione composta    n
        i += 1             # Incremento            n
    return sum_            # Restituzione valore   1
                           # TOTALE: 3n + 4

Il costo della ricerca binaria

  
def binary_search(v, value):          # Numero operazioni
    start = 0                         # 1
    end = len(v) - 1                  # 1

    while start <= end:               # k + 2
        mid = (start + end) // 2      # k + 1

        if v[mid] == value:           # k + 1
            return mid  # Valore trovato!
        elif value < v[mid]:          # k + 1
            end = mid - 1
        else:
            start = mid + 1           # k + 1
    return -1                         # 1

  
Nel caso peggiore, con un vettore di n = 2k elementi, sommando la colonna dei costi si ottiene T(n) = 5k + 9. Applicando il logaritmo in base 2 a entrambi i membri di n = 2k si ricava log2n = k, quindi:

  
T(n) = 5 log2n + 9  → funzione logaritmica

  
La funzione cresce proporzionalmente al logaritmo in base 2 della dimensione dei dati: raddoppiare n aggiunge un solo passo.

Le classi di complessità e la notazione O grande

  
Per confrontare l'efficienza di algoritmi diversi spesso si tralasciano i dettagli e si guarda solo al tipo di crescita per n grande, cioè al comportamento asintotico della funzione di costo. Così si classificano gli algoritmi in classi di complessità.

  
La notazione O (si legge "O grande") indica il limite superiore della crescita della funzione di costo. Per trovarla si tiene il termine che cresce più in fretta e si eliminano costanti e coefficienti:

  

    
funzioneT(n)classe

sort() di Python—O(n log n)

      
print_square, selection_sort3n² + 6n + 2,  2n² + 8n + 2O(n²) — quadratica

      
TSP a forza bruta(n − 1)! percorsiO(n!) — fattoriale

    
  

  
Per esempio, un algoritmo di classe O(n) ha un tempo che cresce linearmente con la dimensione dell'input. Non ci dice il tempo esatto, ma come cresce il tempo al crescere di n.

Come scegliereLe differenze più grandi non si vedono tra funzioni della stessa classe, ma tra classi diverse come O(log n), O(n), O(n²). A parità di classe si preferisce l'algoritmo con il fattore moltiplicativo minore. Tra classi diverse si preferisce in genere quella inferiore: un algoritmo O(log n) è sempre preferibile a uno O(n), salvo quando n è molto piccolo. In questi confronti si rinuncia a contare con precisione le operazioni e si calcola solo la classe.

selection_sort.py — codifica e analisi della complessità

  
Esercizio: prova a scrivere il codice da solo, poi confrontalo con la soluzione. L'indice i scorre il vettore fino al penultimo elemento; min_ memorizza l'indice del minimo trovato nella sezione non ordinata; j scorre gli elementi successivi a i; alla fine si scambiano v[i] e v[min_].

  
Mostra la soluzione
  
def selection_sort(v):                    # Operazioni
    i = 0                                 # 1
    while i < len(v) - 1:                 # n + 1
        min_ = i                          # n
        j = i + 1                         # n
        while j < len(v):                 # n(n + 1)/2 + n
            if v[j] < v[min_]:            # n(n + 1)/2
                min_ = j                  # n(n + 1)/2
            j += 1                        # n(n + 1)/2
        v[i], v[min_] = v[min_], v[i]     # n
        i += 1                            # n

if __name__ == '__main__':
    v = [5, 2, 4, 6, 1, 3]
    selection_sort(v)
    print(v)                              # [1, 2, 3, 4, 5, 6]

Il problema del commesso viaggiatore (TSP)

  
    
    
  • Sono date n città, numerate da 0 a n − 1, e una matrice n × n con i costi per spostarsi da una città all'altra.
